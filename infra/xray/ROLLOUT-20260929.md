# Rollout verification — 2026-09-29

Deployed credential-scoped Xray on the existing Remnawave node with the
`compose.device-revocation.yml` overlay (installed as docker-compose.override.yml).
NET_ADMIN is absent. The user explicitly approved the brief restart and capability
change. Existing shared subscriptions were not mass-migrated.

API and miniapp deployed after the live acceptance gate passed. Production uses
the optional `.env.devices` file with
`REMNAWAVE_DEVICE_SESSION_REVOCATION_ENABLED=true`; the external squad was
already configured. Keep this flag false on unpatched infrastructure.

Verified:

- 54 backend unit tests, mypy (26 modules), frontend production build.
- Patched-core race tests and loopback acceptance: two users, same IP, all three
  transports, live TCP/UDP and reconnect with revoked credentials.
- Real Remnawave/API/DB acceptance container exited 0: device creation/retry,
  slot limit, one-HWID policy, Reality/XHTTP/Hysteria active streams, same-IP
  isolation, UDP on XHTTP/Hysteria, no reissue of revoked credentials.
- Renewal preserves device IDs and remaining-device URL; repeated provisioning
  does not extend twice. Expiry blocks traffic; restoring expiry reconnects the
  retained Hysteria client without restarting it. Revoked device remains blocked.
  Restoration is asynchronous, not guaranteed on the first immediate probe.
- Disposable acceptance users/subscriptions were cleaned up.
- Public readiness: PostgreSQL, Redis and VPN provider true; cabinet HTTP 200;
  unauthenticated migration HTTP 401; feature and device policy configured.

Node watchdog deployment drift was also corrected: the live script still
required retired gRPC TCP/8443 although repository code no longer did. Only that
port check was removed, retaining the production fallback hostname. Watchdog
now returns success and its failure counter is zero. No extra node restart was
needed for this correction.

Rollback assets:

- Node: `/opt/remnanode/backups/device-revoke-20260928/` (original compose,
  watchdog), original node image retained.
- App: `/opt/vpn-platform/.deploy-backups/devices-20260929/` (source, compose,
  database dump), local `before-devices-20260929` API and miniapp images.
- Old API snapshot failed because containerd lacked an old image layer. No
  production mutation occurred at that stage. The rollback API image was rebuilt
  from the backed-up old source before deployment proceeded.

Remaining limitation: background history requests to the pre-existing
`/api/bandwidth-stats/users/...` endpoint returned 404 for three provider users.
The cause and completeness of historical traffic statistics are not established
by this rollout. Do not report those statistics as verified or replace missing
history with zero. This release does not promise that arbitrary client/ISP/OS
failures can never interrupt VPN traffic.

Customer action for an existing shared subscription: Devices → switch to personal
connections (explicit confirmation stops the old shared links), then add each
device and import its own link into Happ. Never perform that migration silently.
