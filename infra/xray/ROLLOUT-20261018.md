# Hysteria UDP compatibility repair — 18 October 2026

## Cause and repair

Happ 5.7.0 on the tested Mac embeds Xray 26.7.28. After 2026-09-01 UTC that
client omits QUIC max_datagram_frame_size. The previous patched 26.3.27 server
requires that advertisement before returning DATAGRAMs. HTTPS still worked,
so the HTTPS observatory kept selecting Hysteria instead of the XHTTP fallback.
This was reproduced with standalone official clients bound to the physical
interface, without disconnecting Happ: 26.7.28 passed HTTPS but failed both STUN
destinations; 26.3.27 passed both. Discord voice setup failed on Hysteria and
recovered on XHTTP before the server change.

Rebased credential-scoped revocation on upstream v26.7.28, commit
`5ca6f4b7d4dc20a881d4330e498892697627ec0c`. The newer server accepts omitted
DATAGRAM advertisements. Hysteria route-specific user views retain their
canonical generation's revocation signal. No IP-scoped disconnection or
NET_ADMIN was added, and production TLS verification/private-target protection
was not relaxed.

## Limits

Xray 26.3.27's Hysteria client fails the 1400-byte echo payload check with both
the old and new server; this pre-existing large-packet issue is not advertised
as repaired by a server upgrade. Use a current client or XHTTP for affected
legacy clients. The default loopback verifier retains the strict large-packet
checks; the legacy small-packet matrix is explicitly selected using
`E2E_UDP_PAYLOAD_SIZES=32,900`.

A successful end-to-end Telegram call was not observed after rollout. The
shared UDP defect is repaired, but Telegram audio quality is not claimed as
verified. No guarantee of zero loss across every network/device is implied.
